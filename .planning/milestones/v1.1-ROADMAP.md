## Overview

Harden the platform for production deployment by resolving all 36 findings from the unified code review and silent failure audit. Covers security vulnerabilities, production readiness gaps, error handling, test coverage, and code quality. Ordered by severity: emergency fixes first, then security, production readiness, error handling, test coverage, and code quality.

## Phases

### Phase 26: Emergency Fixes

**Goal**: Resolve the three most dangerous issues immediately — a tenant data isolation vulnerability, an exposed API key, and unregistered exception filters that cause unstructured 500 responses.
**Depends on**: Nothing (first phase of v1.1)
**Requirements**: EMER-01, EMER-02, EMER-03
**Plans**: 2 plans

Plans:

- [x] 26-01: RLS bypass safety, global exception filters, non-Error logging
- [x] 26-02: Anthropic API key rotation (human action required) and .env update

**Success Criteria:**

1. `withBypassRLS()` destroys tainted connections on `disableBypassRLS()` failure
2. Anthropic API key rotated; old key invalidated
3. `HttpExceptionFilter` and `SentryExceptionFilter` registered globally via `app.useGlobalFilters()`
4. All unhandled exceptions produce structured JSON error responses
5. Non-Error exceptions in `HttpExceptionFilter` else branch are logged

## Milestone Summary

**Key Decisions:**

- All 5 remediation phases in scope (full hardening, not incremental)
- Phase numbering continues from v1.0 (26-31)
- Source of truth: UNIFIED-AUDIT-REPORT.md (not re-research)
- Controller gap closed via documentation (LOC is decorator overhead, business logic in services)
- Thin coordinator pattern for service decomposition
- RS256 auto-generated in development, env-configured in production
- handleApiError logs to console AND shows toast
- Template Method pattern for BaseAssociationService
- Original audit's top 5 services satisfy QUAL-01 (AI orchestration services deferred)
- ESLint max-lines rule (warn at 500 LOC) added as guardrail

**Issues Resolved:**

- RLS bypass tainted connection leak (CRITICAL)
- Exposed Anthropic API key (CRITICAL)
- 56 vulnerabilities in npm dependencies (pre-existing, not introduced by v1.1)
- Silent failures in 30+ frontend components (now show toast notifications)
- Bare throw new Error() in 31 service/controller instances

**Issues Deferred:**

- 70 services >500 LOC (systemic concern, needs tiered limits and ESLint enforcement)
- npm dependency vulnerabilities (axios, next, webpack, xlsx — require breaking version bumps)
- Full 80% test coverage (foundation phase targets auth + core services; remaining coverage in v1.2)

**Technical Debt Incurred:**

- AI orchestration services (929-1000 LOC) not decomposed — different architectural class than CRUD services
- Pre-commit hook security audit returns warnings due to upstream dependency vulnerabilities
