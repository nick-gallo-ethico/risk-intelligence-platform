## Orphaned Exports (5 found)

### Orphan 1 -- CRITICAL: TenantCacheService / RedisCacheModule (Phase 34)

File: apps/backend/src/common/cache.module.ts
Exports: TenantCacheService with org:{orgId}:{namespace}:{key} key format; wraps @nestjs/cache-manager with Redis
Expected consumers: Services across all modules injecting CACHE_MANAGER
Actual consumers: 0
Verified: grep -r RedisCacheModule returns only cache.module.ts itself
Impact: CRITICAL -- 7+ services inject @Inject(CACHE_MANAGER) with no global provider registered.
Affected services: branding.service.ts, organization.service.ts, notifications/preference.service.ts,
notifications/org-settings.service.ts, operations/hotline-ops/operator-status.service.ts,
portals/ethics/ethics-portal.service.ts, disclosures/services/triage-preview.service.ts.
DashboardModule is shielded (own inline CacheModule), but all other modules are not.
NestJS DI will fail at startup for any module containing these services.

### Orphan 2 -- Medium: JwtWsGuard (Phase 32)

File: apps/backend/src/modules/auth/guards/jwt-ws.guard.ts
What it does: WebSocket JWT guard using configService.get(JWT_SECRET) -- HS256 verification
Actual consumers: 0 -- never imported outside its own spec file
Algorithm conflict: Uses HS256 (JWT_SECRET) but Phase 32 enforces RS256 for all tokens.
If applied with @UseGuards(JwtWsGuard), all WebSocket connections fail authentication.
AiGateway correctly uses JwtKeyService directly -- this guard is bypassed and orphaned.
Impact: Medium -- harmless dead code; becomes a security trap if reused by developers.

### Orphan 3 -- Medium: processRemindersInBatches() (Phase 34)

File: apps/backend/src/modules/campaigns/campaign-reminder.service.ts line 139
What it does: Cursor-based batch processing (batch size 100) for 100K+ campaign assignments
Expected caller: CampaignReminderProcessor.scheduledReminderCheck() at line 117
Actual caller: None -- scheduledReminderCheck() at line 122 calls findAssignmentsNeedingReminders() instead
Verified: grep -r processRemindersInBatches returns only its own definition
Impact: Medium -- Phase 34 scalability fix shipped in wrong method. Large tenants will exhaust heap
during daily 8AM reminder cron when all pending assignments load into memory simultaneously.

### Orphan 4 -- Low: CaseInfoSummary import (Phase 25.1)

File: apps/frontend/src/app/(authenticated)/cases/[id]/page.tsx line 20
Import: import { CaseInfoSummary } from @/components/cases/case-info-summary
JSX usage: 0 -- component imported but not rendered anywhere in the page
Impact: Low -- dead import left from Phase 25.1 refactor. No runtime error.

### Orphan 5 -- High: theme-colors.ts under-adopted (Phase 22)

File: apps/frontend/src/lib/theme-colors.ts
Provides: statusColors, severityColors, semanticColors with dark: variants
Adoption: Used in approximately 5 files
Files bypassing it: 141 component files with hardcoded Tailwind color classes (no dark: variants)
Impact: HIGH -- dark mode visually broken across 141 files. The utility is correct;
the gap is breadth of adoption.
