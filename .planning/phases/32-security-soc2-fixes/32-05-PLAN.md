<task type="auto">
  <name>Task 2: Add MaxLength to LoginDto Password</name>
  <files>apps/backend/src/modules/auth/dto/login.dto.ts</files>
  <action>
Add @MaxLength(72) to prevent bcrypt CPU exhaustion attacks.

bcrypt implementations typically hash only the first 72 bytes of input, but still read the entire input. A 1MB password can cause multi-second CPU consumption during the hash computation.

1. Add MaxLength import and decorator:

   ```typescript
   import { IsEmail, IsString, MinLength, MaxLength } from "class-validator";
   import { ApiProperty } from "@nestjs/swagger";

   export class LoginDto {
     @ApiProperty({
       description: "User email address",
       example: "user@example.com",
     })
     @IsEmail({}, { message: "Please provide a valid email address" })
     email: string;

     @ApiProperty({
       description: "User password",
       example: "securePassword123",
       minLength: 8,
       maxLength: 72,
     })
     @IsString()
     @MinLength(8, { message: "Password must be at least 8 characters" })
     @MaxLength(72, { message: "Password cannot exceed 72 characters" }) // SEC-07: Prevent bcrypt CPU exhaustion
     password: string;
   }
   ```

2. Check for other password DTOs that might need the same fix:
   - Search: `grep -rn "@IsString().*password\|password.*@IsString" apps/backend/src/modules/auth/dto/`
   - Apply @MaxLength(72) to any password fields in other DTOs (e.g., ChangePasswordDto, RegisterDto)
     </action>
     <verify>
     Verify MaxLength on password: `grep -A2 "password:" apps/backend/src/modules/auth/dto/login.dto.ts | grep -q "MaxLength" && echo "MaxLength present"`
     Verify import: `grep -n "MaxLength" apps/backend/src/modules/auth/dto/login.dto.ts`
