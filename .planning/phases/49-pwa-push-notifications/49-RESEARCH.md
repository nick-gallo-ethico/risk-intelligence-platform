# Phase 49: PWA & Push Notifications - Research

**Researched:** 2026-02-28
**Domain:** Progressive Web Apps, Web Push API, Service Workers, Offline-First Architecture
**Confidence:** HIGH

## Summary

This phase builds upon significant existing PWA infrastructure already in place. The codebase includes `@ducanh2912/next-pwa` v10.2.9 with configured service worker, `manifest.json`, offline fallback page, Dexie IndexedDB database with encryption for draft storage, and background sync configuration for form submissions. The notification module has WebSocket gateway with tenant-isolated rooms and event-driven architecture ready for push notification integration.

The primary work involves: (1) Adding `PUSH` as a new NotificationChannel, (2) Creating PushSubscription model with tenant isolation, (3) Implementing WebPushService using the `web-push` npm library, (4) Extending the service worker to handle push events with tenant-scoped cache isolation, and (5) Connecting push triggers to existing SLA and campaign reminder events.

**Primary recommendation:** Extend existing notification infrastructure with web-push delivery channel rather than building parallel notification system. The event-driven architecture (EventEmitter + BullMQ) already handles SLA warnings, campaign reminders, and case status changes - push notifications slot into this as another delivery channel.

### Pattern 3: Tenant-Scoped Service Worker Cache

**What:** Namespace all cache entries by tenant to prevent cross-tenant data leakage
**When to use:** All cached API responses, especially branding and user-specific data
**Example:**

```typescript
// Source: OWASP Multi-Tenant Security + existing project patterns
// apps/frontend/src/app/sw.ts (custom service worker)

const getTenantCacheName = (tenant: string, cacheType: string): string => {
  return `tenant-${tenant}-${cacheType}-v1`;
};

// On login/tenant switch - pass tenant via postMessage
self.addEventListener("message", (event) => {
  if (event.data.type === "SET_TENANT") {
    self.currentTenant = event.data.tenant;
  }
  if (event.data.type === "CLEAR_TENANT_CACHE") {
    // Clear all caches for this tenant on logout
    caches.keys().then((keys) => {
      keys
        .filter((k) => k.startsWith(`tenant-${event.data.tenant}`))
        .forEach((k) => caches.delete(k));
    });
  }
});
```

### Pattern 4: Push Event Handler with Notification Display

**What:** Service worker push event handler that displays notifications
**When to use:** Receiving push messages from backend
**Example:**

```typescript
// Source: MDN Push API + web.dev best practices
// apps/frontend/public/custom-sw.js

self.addEventListener("push", (event) => {
  const data = event.data?.json() ?? {};

  const options = {
    body: data.body,
    icon: "/icons/icon-192.png",
    badge: "/icons/badge-72.png",
    tag: data.tag || "default",
    data: {
      url: data.url,
      entityType: data.entityType,
      entityId: data.entityId,
    },
    actions: data.actions || [],
    requireInteraction: data.urgent || false,
  };

  // CRITICAL: waitUntil keeps SW alive during async operation
  event.waitUntil(self.registration.showNotification(data.title, options));
});

self.addEventListener("notificationclick", (event) => {
  event.notification.close();

  const url = event.notification.data?.url || "/";
  event.waitUntil(
    clients.matchAll({ type: "window" }).then((windowClients) => {
      // Focus existing window or open new
      for (const client of windowClients) {
        if (client.url === url && "focus" in client) {
          return client.focus();
        }
      }
      return clients.openWindow(url);
    }),
  );
});
```

### Pattern 5: VAPID Configuration

**What:** Secure storage and usage of VAPID keys
**When to use:** Server-side push message signing
**Example:**

```typescript
// Source: web-push library documentation
// apps/backend/src/modules/notifications/services/web-push.service.ts

@Injectable()
export class WebPushService {
  constructor(private configService: ConfigService) {
    webpush.setVapidDetails(
      this.configService.getOrThrow("VAPID_SUBJECT"), // 'mailto:push@ethico.com'
      this.configService.getOrThrow("VAPID_PUBLIC_KEY"),
      this.configService.getOrThrow("VAPID_PRIVATE_KEY"),
    );
  }

  async sendNotification(
    subscription: PushSubscriptionData,
    payload: object,
  ): Promise<void> {
    try {
      await webpush.sendNotification(
        {
          endpoint: subscription.endpoint,
          keys: {
            p256dh: subscription.p256dhKey,
            auth: subscription.authKey,
          },
        },
        JSON.stringify(payload),
        {
          TTL: 60 * 60 * 24, // 24 hours
          urgency: payload.urgent ? "high" : "normal",
        },
      );
    } catch (error) {
      if (error.statusCode === 410) {
        // Subscription expired - remove from database
        await this.removeExpiredSubscription(subscription.endpoint);
      }
      throw error;
    }
  }
}
```

### Anti-Patterns to Avoid

- **Global service worker cache:** Never cache user data without tenant prefix - causes cross-tenant data leakage
- **Push without user gesture:** Never call `pushManager.subscribe()` without explicit user interaction - browsers require it
- **Ignoring 410 responses:** Always handle 410 (Gone) from push service by removing stale subscriptions
- **Blocking push event:** Always use `event.waitUntil()` - service workers terminate immediately otherwise
- **Storing VAPID keys in code:** Always use environment variables for VAPID private key

## Don't Hand-Roll

Problems that look simple but have existing solutions:

| Problem                 | Don't Build        | Use Instead                        | Why                                         |
| ----------------------- | ------------------ | ---------------------------------- | ------------------------------------------- |
| VAPID key generation    | Custom crypto      | `web-push generate-vapid-keys` CLI | Correct curve (P-256), proper encoding      |
| Push payload encryption | Custom AES         | `web-push.sendNotification()`      | Handles aes128gcm/aesgcm automatically      |
| Subscription storage    | Raw localStorage   | Database with RLS                  | Multi-device support, tenant isolation      |
| Background sync         | Custom polling     | Workbox BackgroundSync plugin      | Already configured in next.config.js        |
| Offline form queue      | Custom retry logic | Dexie + BackgroundSync             | Already implemented in ethics-offline-db.ts |

**Key insight:** The existing codebase already implements offline form queuing, background sync, and IndexedDB encryption. Push notifications slot into existing notification architecture - just add PUSH as another channel.

## Common Pitfalls

### Pitfall 1: Cross-Tenant Cache Pollution

**What goes wrong:** Service worker caches user-specific data (branding, preferences) that leaks between tenants
**Why it happens:** Default Workbox caching uses URL as cache key without tenant context
**How to avoid:** Namespace all cache names with tenant ID, clear tenant caches on logout
**Warning signs:** User sees another tenant's branding after switching accounts

### Pitfall 2: Stale Push Subscriptions

**What goes wrong:** Backend sends to expired subscriptions, causing errors and wasted resources
**Why it happens:** Subscriptions expire silently when user uninstalls browser or clears data
**How to avoid:** Handle 410 responses from push service, periodically ping subscriptions
**Warning signs:** High percentage of push failures, 410 status codes in logs

### Pitfall 3: Permission Prompt Fatigue

**What goes wrong:** Users dismiss permission prompts, cannot receive notifications
**Why it happens:** Prompting immediately on page load without context
**How to avoid:** Prompt only after meaningful action (e.g., submitting report, enabling feature in settings)
**Warning signs:** Low subscription rates, "blocked" permission state

### Pitfall 4: Service Worker Update Stuck

**What goes wrong:** Users stuck on old service worker version, missing features/fixes
**Why it happens:** Service worker lifecycle requires refresh + no active tabs
**How to avoid:** Use `skipWaiting: true` (already configured), show update banner
**Warning signs:** Users report missing features, old cached content

### Pitfall 5: IndexedDB Encryption Key Loss

**What goes wrong:** User drafts become unreadable after browser data clear
**Why it happens:** Encryption key stored in localStorage, cleared with "clear all data"
**How to avoid:** Document limitation, show appropriate error message (already handled in ethics-offline-db.ts)
**Warning signs:** `_decryptionFailed: true` in draft records

## Code Examples

### Web Push Service (Backend)

```typescript
// Source: web-push npm documentation + NestJS patterns
@Injectable()
export class WebPushService {
  private readonly logger = new Logger(WebPushService.name);

  constructor(
    private readonly configService: ConfigService,
    private readonly prisma: PrismaService,
  ) {
    webpush.setVapidDetails(
      this.configService.getOrThrow<string>("VAPID_SUBJECT"),
      this.configService.getOrThrow<string>("VAPID_PUBLIC_KEY"),
      this.configService.getOrThrow<string>("VAPID_PRIVATE_KEY"),
    );
  }

  async sendToUser(
    organizationId: string,
    userId: string,
    payload: PushPayload,
  ): Promise<PushResult[]> {
    const subscriptions = await this.prisma.pushSubscription.findMany({
      where: { organizationId, userId },
    });

    const results = await Promise.allSettled(
      subscriptions.map((sub) => this.sendToSubscription(sub, payload)),
    );

    return results.map((r, i) => ({
      endpoint: subscriptions[i].endpoint,
      success: r.status === "fulfilled",
      error: r.status === "rejected" ? r.reason : undefined,
    }));
  }

  private async sendToSubscription(
    subscription: PushSubscription,
    payload: PushPayload,
  ): Promise<void> {
    try {
      await webpush.sendNotification(
        {
          endpoint: subscription.endpoint,
          keys: { p256dh: subscription.p256dhKey, auth: subscription.authKey },
        },
        JSON.stringify(payload),
        { TTL: 86400, urgency: payload.urgent ? "high" : "normal" },
      );
    } catch (error: any) {
      if (error.statusCode === 410 || error.statusCode === 404) {
        // Subscription invalid - remove
        await this.prisma.pushSubscription.delete({
          where: { id: subscription.id },
        });
        this.logger.log(`Removed expired subscription ${subscription.id}`);
      }
      throw error;
    }
  }
}
```

### Push Subscription Client (Frontend)

```typescript
// Source: Push API MDN documentation
export async function subscribeToPush(
  tenantSlug: string,
  vapidPublicKey: string,
): Promise<PushSubscription | null> {
  if (!("PushManager" in window)) {
    console.warn("Push notifications not supported");
    return null;
  }

  const permission = await Notification.requestPermission();
  if (permission !== "granted") {
    return null;
  }

  const registration = await navigator.serviceWorker.ready;
  const subscription = await registration.pushManager.subscribe({
    userVisibleOnly: true,
    applicationServerKey: urlBase64ToUint8Array(vapidPublicKey),
  });

  // Send to backend
  await fetch(`/api/v1/push-subscriptions`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      endpoint: subscription.endpoint,
      keys: {
        p256dh: arrayBufferToBase64(subscription.getKey("p256dh")),
        auth: arrayBufferToBase64(subscription.getKey("auth")),
      },
    }),
  });

  return subscription;
}

function urlBase64ToUint8Array(base64String: string): Uint8Array {
  const padding = "=".repeat((4 - (base64String.length % 4)) % 4);
  const base64 = (base64String + padding).replace(/-/g, "+").replace(/_/g, "/");
  const rawData = window.atob(base64);
  return Uint8Array.from(rawData, (c) => c.charCodeAt(0));
}
```

## State of the Art

| Old Approach                 | Current Approach                                    | When Changed | Impact                                 |
| ---------------------------- | --------------------------------------------------- | ------------ | -------------------------------------- |
| GCM (Google Cloud Messaging) | VAPID (Voluntary Application Server Identification) | 2016         | No Google dependency, self-hosted keys |
| aesgcm encoding              | aes128gcm encoding                                  | 2018         | Better compression, still supported    |
| next-pwa (original)          | @ducanh2912/next-pwa or @serwist/next               | 2023         | Original unmaintained                  |
| Manual service worker        | Workbox integration                                 | 2020         | Easier caching strategies              |

**Deprecated/outdated:**

- GCM API keys: Use VAPID instead, no Google account needed
- `@nickvazquez/next-pwa`: Original next-pwa, unmaintained since 2022
- Custom push encryption: Use web-push library, handles all encoding

## Open Questions

1. **Migration from @ducanh2912/next-pwa to @serwist/next**
   - What we know: Both work, @serwist is official successor
   - What's unclear: Is migration worth the effort given current setup works?
   - Recommendation: Keep @ducanh2912/next-pwa for now; migrate if issues arise

2. **Push Notification Grouping/Collapsing**
   - What we know: Web Push supports `tag` for replacement, `topic` for coalescing
   - What's unclear: Best UX for multiple SLA warnings vs single digest
   - Recommendation: Use `tag` = `${entityType}-${entityId}` to replace per-entity

3. **Offline Form Submission Queue - Edge Cases**
   - What we know: Background sync configured, Dexie stores pending submissions
   - What's unclear: Handling when user submits offline, then logs out
   - Recommendation: Queue submissions are tenant-scoped, clear on logout
